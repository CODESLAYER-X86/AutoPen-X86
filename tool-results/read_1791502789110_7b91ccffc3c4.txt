     8→     8→
     9→     9→# 0. Purpose
    10→    10→
    11→    11→Implement the deterministic interaction layer between the autonomous agent system and authorized web targets.
    12→    12→
    13→    13→This phase provides:
    14→    14→
    15→    15→* browser automation
    16→    16→* HTTP interaction
    17→    17→* browser network observation
    18→    18→* request/response capture
    19→    19→* replay
    20→    20→* controlled mutation
    21→    21→* multi-identity sessions
    22→    22→* cookies and browser storage
    23→    23→* DOM inspection
    24→    24→* JavaScript/resource discovery
    25→    25→* WebSocket observation
    26→    26→* screenshots
    27→    27→* browser traces
    28→    28→* downloads
    29→    29→* HTTP normalization
    30→    30→* traffic correlation
    31→    31→* tool registry
    32→    32→* policy enforcement at the tool boundary
    33→    33→* MCP-compatible tool abstraction where useful
    34→    34→
    35→    35→This phase must remain deterministic.
    36→    36→
    37→    37→The LLM decides **what should be investigated**.
    38→    38→
    39→    39→The tool layer determines **how the operation is performed**.
    40→    40→
    41→    41→---

    84→    84→
    85→    85→# 2. Browser Technology
    86→    86→
    87→    87→Use **Playwright** as the browser automation abstraction.
    88→    88→
    89→    89→Do not expose Playwright directly to the LLM.
    90→    90→
    91→    91→Create an internal browser service.
    92→    92→
    93→    93→Conceptually:
    94→    94→
    95→    95→```text
    96→    96→Agent
    97→    97→ ↓
    98→    98→browser tool
    99→    99→ ↓
   100→   100→Browser Service
   101→   101→ ↓
   102→   102→Playwright
   103→   103→ ↓
   104→   104→Chromium/other supported browser
   105→   105→```
   106→   106→
   107→   107→The browser service owns:
   108→   108→
   109→   109→* browser lifecycle
   110→   110→* context lifecycle
   111→   111→* page lifecycle
   112→   112→* action execution
   113→   113→* event capture
   114→   114→* artifact capture
   115→   115→* cleanup
   116→   116→
   117→   117→---
   118→   118→
   119→   119→# 3. Browser Isolation
   120→   120→
   121→   121→Every engagement must receive isolated browser resources.
   122→   122→
   123→   123→At minimum:
   124→   124→
   125→   125→```text
   126→   126→Engagement
   127→   127→    ↓
   128→   128→BrowserSession
   129→   129→    ↓
   130→   130→BrowserContext
   131→   131→    ↓
   132→   132→Page(s)
   133→   133→```
   134→   134→
   135→   135→Do not share cookies or localStorage between identities.
   136→   136→
   137→   137→Example:
   138→   138→
   139→   139→```text
   140→   140→Context A → Anonymous
   141→   141→Context B → User A
   142→   142→Context C → User B
   143→   143→Context D → Admin
   144→   144→```
   145→   145→
   146→   146→These contexts must be independently disposable.
   147→   147→
   148→   148→---
   149→   149→
   150→   150→# 4. Identity-to-Browser Mapping
   151→   151→
   152→   152→Create a deterministic relationship:
   153→   153→
   154→   154→```text
   155→   155→Identity
   156→   156→   |
   157→   157→   +---- BrowserContext
   158→   158→   |
   159→   159→   +---- HTTP Session
   160→   160→```
   161→   161→
   162→   162→A worker should specify:
   163→   163→
   164→   164→```text
   165→   165→identity_id = ID_A
   166→   166→```
   167→   167→
   168→   168→rather than directly manipulating cookies.
   169→   169→
   170→   170→The session manager resolves the identity to its appropriate authenticated state.
   171→   171→
   172→   172→---
   173→   173→
   174→   174→# 5. Browser Context Lifecycle
   175→   175→
   176→   176→Implement:
   177→   177→
   178→   178→```text
   179→   179→CREATE
   180→   180→INITIALIZE
   181→   181→READY
   182→   182→ACTIVE
   183→   183→PAUSED
   184→   184→EXPIRED
   185→   185→CLOSING
   186→   186→CLOSED
   187→   187→FAILED
   188→   188→```
   189→   189→
   190→   190→Context cleanup must happen even if a worker crashes.
   191→   191→
   192→   192→Use `finally`-style resource cleanup.
   193→   193→
   194→   194→---
   195→   195→
   196→   196→# 6. Browser Profiles
   197→   197→
   198→   198→Do not use persistent browser profiles by default.
   199→   199→
   200→   200→Prefer isolated Playwright contexts.
   201→   201→
   202→   202→Persistent profiles should be an explicit feature.
   203→   203→
   204→   204→This prevents:
   205→   205→
   206→   206→* accidental credential reuse
   207→   207→* cross-engagement contamination
   208→   208→* stale cookies
   209→   209→* state leakage
   210→   210→
   211→   211→---
   212→   212→
   213→   213→# 7. Browser Actions
   214→   214→
   215→   215→Create deterministic browser operations.
   216→   216→
   217→   217→Initial actions:
   218→   218→
   219→   219→```text
   220→   220→browser.navigate
   221→   221→browser.go_back
   222→   222→browser.go_forward
   223→   223→browser.reload
   224→   224→
   225→   225→browser.click
   226→   226→browser.fill
   227→   227→browser.select_option
   228→   228→browser.check
   229→   229→browser.uncheck
   230→   230→
   231→   231→browser.press
   232→   232→browser.hover
   233→   233→
   234→   234→browser.wait_for
   235→   235→browser.wait_for_url
   236→   236→browser.wait_for_selector
   237→   237→
   238→   238→browser.screenshot
   239→   239→browser.snapshot
   240→   240→```
   241→   241→
   242→   242→Do not allow arbitrary JavaScript execution by default.
   243→   243→
   244→   244→If arbitrary script evaluation is later required, place it behind a separate high-risk capability.
   245→   245→
   246→   246→---
   247→   247→
   248→   248→# 8. Browser Action Schema
   249→   249→
   250→   250→Each action must be structured.
   251→   251→
   252→   252→Example:
   253→   253→
   254→   254→```json id="q9pzj7"
   255→   255→{
   256→   256→  "context_id": "CTX_01",
   257→   257→  "action": "CLICK",
   258→   258→  "selector": {
   259→   259→    "strategy": "role",
   260→   260→    "value": "button",
   261→   261→    "name": "Login"
   262→   262→  },
   263→   263→  "timeout_ms": 5000
   264→   264→}
   265→   265→```
   266→   266→
   267→   267→Do not allow a worker to submit arbitrary JavaScript as a substitute for normal browser actions.
   268→   268→
   269→   269→---
   270→   270→
   271→   271→# 9. Selector Strategy
   272→   272→
   273→   273→Support deterministic selector strategies:
   274→   274→
   275→   275→```text id="plq1fr"
   276→   276→role
   277→   277→text
   278→   278→label
   279→   279→placeholder
   280→   280→css
   281→   281→xpath
   282→   282→test_id
   283→   283→```
   284→   284→
   285→   285→Prefer stable semantic selectors.
   286→   286→
   287→   287→The browser service should normalize selector errors.
   288→   288→

   362→   362→context_id
   363→   363→page_id

   373→   373→
   374→   374→For each response:
   375→   375→
   376→   376→```text id="4x6h7j"

   378→   378→status

   390→   390→# 13. Request Correlation
   391→   391→
   392→   392→Every browser request must receive a unique internal ID.
   393→   393→
   394→   394→Example:
   395→   395→
   396→   396→```text id="oy5c4r"
   397→   397→Browser Event
   398→   398→    |
   399→   399→    v
   400→   400→REQ_BROWSER_001
   401→   401→    |
   402→   402→    +── request
   403→   403→    +── response
   404→   404→    +── page
   405→   405→    +── context
   406→   406→    +── identity
   407→   407→    +── task
   408→   408→    +── evidence
   409→   409→```
   410→   410→
   411→   411→This lets the system trace:
   412→   412→
   413→   413→```text
   414→   414→user clicked button

   416→   416→→ API request occurred
   417→   417→→ response returned
   418→   418→→ DOM changed

   423→   423→# 14. Browser-to-HTTP Relationship
   424→   424→
   425→   425→Browser and HTTP systems must share a common request representation.
   426→   426→
   427→   427→Do not create incompatible models.
   428→   428→
   429→   429→Create a normalized:
   430→   430→
   431→   431→```text id="h9plz3"
   432→   432→HttpRequest
   433→   433→HttpResponse
   434→   434→```
   435→   435→
   436→   436→representation.
   437→   437→
   438→   438→Browser traffic can then be promoted into the HTTP testing subsystem.
   439→   439→
   440→   440→Example:
   441→   441→
   442→   442→```text id="3t2qws"
   443→   443→Browser:
   444→   444→POST /api/profile
   445→   445→
   446→   446→        ↓
   447→   447→
   448→   448→Captured request
   449→   449→
   450→   450→        ↓
   451→   451→
   452→   452→HTTP request record
   453→   453→
   454→   454→        ↓
   455→   455→
   456→   456→HTTP Worker
   457→   457→
   458→   458→        ↓
   459→   459→
   460→   460→Replay / controlled mutation
   461→   461→```
   462→   462→
   463→   463→This is a core capability.
   464→   464→

   466→   466→
   467→   467→# 15. HTTP Engine
   468→   468→
   469→   469→Implement an independent HTTP client service.
   470→   470→
   471→   471→It should support:
   472→   472→
   473→   473→```text id="g2ct9a"
   474→   474→GET
   475→   475→POST
   476→   476→PUT
   477→   477→PATCH
   478→   478→DELETE
   479→   479→HEAD
   480→   480→OPTIONS
   481→   481→```
   482→   482→
   483→   483→Potentially other methods later.
   484→   484→
   485→   485→Use a mature HTTP implementation.
   486→   486→
   487→   487→Do not implement HTTP from raw TCP unless a specialized feature later requires it.
   488→   488→
   489→   489→---
