     1→# Autonomous Web Pentesting & CTF System
     2→
     3→## Implementation Specification — Part 2 of 8
     4→
     5→### Strategic Leader, Tactical Workers, Task Compiler, Hypothesis Engine, Scheduling, Memory, and Autonomous Decision Loop
     6→
     7→---
     8→
     9→# 0. Purpose
    10→
    11→Implement the agent operating system that sits between the application's persistent state and the security-testing tools.
    12→
    13→The system must support:
    14→
    15→* one strategic reasoning model
    16→* multiple specialized tactical workers
    17→* deterministic orchestration
    18→* structured task creation
    19→* hypothesis-driven investigation
    20→* context-efficient worker prompts
    21→* token/quota management
    22→* task prioritization
    23→* parallel and sequential execution
    24→* evidence-driven replanning
    25→* dead-end avoidance
    26→* verification
    27→* graceful failure
    28→
    29→The system must NOT become a collection of independent chatbots.
    30→
    31→There is one authoritative strategic controller.
    32→
    33→Workers are disposable tactical specialists.
    34→
    35→Persistent state belongs to the application.
    36→
    37→---
    38→

   159→# 4. Strategic Leader
   160→
   161→The strategic model is the **commander**.
   162→
   163→Use the configured strategic model from Part 1.
   164→
   165→Do not hard-code a specific model identifier.
   166→
   167→Its responsibilities are:
   168→
   169→### Understand
   170→
   171→* engagement objective
   172→* scope
   173→* available identities
   174→* discovered assets
   175→* current attack surface
   176→* challenge description
   177→* relevant observations
   178→
   179→### Reason
   180→
   181→* identify promising attack surfaces
   182→* generate hypotheses
   183→* rank hypotheses
   184→* recognize patterns
   185→* interpret CTF clues
   186→* identify missing information
   187→* decide which investigation has the highest expected value
   188→
   189→### Plan
   190→
   191→* create investigation tasks
   192→* order dependent tasks
   193→* parallelize independent tasks
   194→* request knowledge
   195→* request browser investigation
   196→* request HTTP investigation
   197→* request source analysis
   198→
   199→### Replan
   200→
   201→After every meaningful result:
   202→
   203→* update hypotheses
   204→* invalidate assumptions
   205→* create new hypotheses
   206→* abandon dead ends
   207→* reprioritize tasks
   208→* request verification
   209→
   210→### Stop
   211→
   212→Stop when:
   213→
   214→* objective is satisfied
   215→* findings are sufficiently verified
   216→* investigation budget is exhausted
   217→* no meaningful hypotheses remain
   218→* scope prevents further testing
   219→* operator pauses/cancels
   220→* system safety policy requires stopping
   221→

   223→
   224→# 5. Leader Must Not Become a Checklist Generator
   225→
   226→Do not implement:
   227→
   228→```text
   229→recon
   230→then auth
   231→then SQLi
   232→then XSS
   233→then IDOR
   234→...
   235→```
   236→
   237→as the mandatory algorithm.
   238→
   239→Instead implement:
   240→
   241→```text
   242→OBSERVATIONS
   243→      ↓
   244→HYPOTHESES
   245→      ↓
   246→EXPECTED INFORMATION GAIN
   247→      ↓
   248→TEST SELECTION
   249→      ↓
   250→RESULT
   251→      ↓
   252→HYPOTHESIS UPDATE
   253→      ↓
   254→REPLAN
   255→```
   256→
   257→The security methodology is a source of candidate tests, not an inflexible sequence.
   258→

   261→# 6. Leader Context Assembly
   262→
   263→Never send the complete database to the leader.
   264→
   265→Construct a context projection.
   266→
   267→The leader should receive:
   268→
   269→```text
   270→Engagement objective
   271→Scope summary
   272→Current assets
   273→Relevant endpoints
   274→Identity summary
   275→Current workflow state
   276→Active hypotheses
   277→Recent observations
   278→Relevant evidence summaries
   279→Recent tests
   280→Dead ends
   281→Relevant knowledge
   282→Pending tasks
   283→Resource/quota state
   284→```
   285→
   286→Do not include irrelevant historical information.
   287→
   288→---
   289→
   290→# 7. Context Priority
   291→
   292→When context must be reduced, prioritize:
   293→
   294→```text
   295→1. Scope
   296→2. Current objective
   297→3. Confirmed facts
   298→4. Active hypotheses
   299→5. Recent observations
   300→6. Unresolved anomalies
   301→7. Relevant evidence
   302→8. Recent tests
   303→9. Dead ends
   304→10. Historical background
   305→```
   306→
   307→Never truncate scope information merely to save tokens.
   308→

   342→# 9. Strategic Decision Schema
   343→
   344→The leader must return a validated structured decision.
   345→
   346→Possible decisions:
   347→
   348→```text
   349→CREATE_TASK
   350→CREATE_PARALLEL_TASKS
   351→UPDATE_HYPOTHESIS
   352→REQUEST_KNOWLEDGE
   353→REQUEST_RECON
   354→REQUEST_VERIFICATION
   355→WAIT
   356→STOP
   357→PAUSE
   358→```
   359→
   360→Example:
   361→
   362→```json
   363→{
   364→  "decision": "CREATE_TASK",
   365→  "objective": "Determine whether object authorization is enforced.",
   366→  "task_type": "AUTHORIZATION_ANALYSIS",
   367→  "priority": 0.91,
   368→  "reasoning_summary": "Two object identifiers were observed and authorization behavior has not yet been compared.",
   369→  "inputs": {
   370→    "endpoint_id": "EP_102",
   371→    "identities": ["ID_01", "ID_02"]
   372→  }
   373→}
   374→```
   375→
   376→Do not expose private chain-of-thought or require the model to produce hidden reasoning.
   377→
   378→Store only concise decision rationale sufficient for auditability.
   379→

   382→# 10. Decision Validation
   383→
   384→Every leader decision must pass:
   385→
   386→```text
   387→schema validation
   388→        ↓
   389→semantic validation
   390→        ↓
   391→engagement validation
   392→        ↓
   393→scope validation
   394→        ↓
   395→permission validation
   396→        ↓
   397→resource validation
   398→        ↓
   399→duplicate-test validation
   400→        ↓
   401→scheduler
   402→```
   403→
   404→Invalid decisions are rejected.
   405→
   406→The rejection should be converted into a machine-readable event.

   410→# 11. Tactical Workers
   411→
   412→Workers are narrow specialists.
   413→
   414→Initial logical worker types:
   415→
   416→```text
   417→HTTP_WORKER
   418→BROWSER_WORKER
   419→SOURCE_WORKER
   420→ANALYSIS_WORKER
   421→```
   422→
   423→Later specialized workers can be added without redesigning the scheduler.
   424→
   425→All workers should use the same worker runtime.
   426→
   427→---
   428→
   429→# 12. Gemma Worker Philosophy
   430→
   431→The tactical model should receive **small tasks**.
   432→
   433→Never send:
   434→
   435→```text
   436→entire engagement
   437→+
   438→all requests
   439→+
   440→all responses
   441→+
   442→all source code
   443→+
   444→all knowledge
   445→```
   446→
   447→Instead:
   448→
   449→```text
   450→TASK
   451→+
   452→RELEVANT CONTEXT
   453→+
   454→RELEVANT EVIDENCE
   455→+
   456→AVAILABLE TOOLS
   457→+
   458→EXPECTED OUTPUT
   459→```
   460→
   461→The goal is to keep worker prompts compact.
   462→

   464→

   469→Conceptually:

   476→  "scope": {

   502→The worker does not decide its own unlimited scope.

   506→# 14. Task Compiler
   507→
   508→Implement:
   509→
   510→```text
   511→Task Compiler
   512→```
   513→
   514→Its purpose is to transform a strategic decision into the smallest useful worker context.
   515→
   516→Input:
   517→
   518→```text
   519→leader decision
   520→+
   521→database state
   522→+
   523→hypothesis
   524→+
   525→relevant evidence
   526→+
   527→tool capabilities
   528→```
   529→
   530→Output:
   531→
   532→```text
   533→compact worker task
   534→```
   535→
   536→The compiler must perform retrieval.
   537→
   538→Do not simply stringify the entire database.
   539→
   540→---
   541→
   542→# 15. Context Compression
   543→
   544→The Task Compiler should prefer:
   545→
   546→```text
   547→structured facts
   548→```
   549→
   550→over prose.
   551→
   552→Instead of:
   553→
   554→```text
   555→"This endpoint was discovered several minutes ago..."
   556→```
   557→
   558→prefer:
   559→
   560→```json
   561→{
   562→  "method": "GET",
   563→  "path": "/api/users/{id}",
   564→  "auth_required": true,
   565→  "observed_ids": ["381", "382"]
   566→}
   567→```
   568→
   569→Use prose only where reasoning requires it.

   576→
   577→Example:
   578→
   579→```json
   580→{
   581→  "task_id": "TASK_123",
   582→  "status": "COMPLETED",
   583→  "observations": [
   584→    {
   585→      "type": "AUTHORIZATION_BEHAVIOR",
   586→      "description": "Identity A received object data associated with Identity B.",
   587→      "confidence": 0.91
   588→    }
   589→  ],
   590→  "evidence_ids": [
   591→    "EVD_900",

   595→    {
   596→      "hypothesis_id": "H_17",
   597→      "change": "INCREASE_CONFIDENCE",
   598→      "confidence": 0.86

   608→Do not permit arbitrary worker-generated database mutations.
   609→
   610→The orchestrator interprets the result.

   614→# 17. Worker Status
   615→
   616→Workers may return:
   617→
   618→```text
   619→COMPLETED
   620→PARTIAL
   621→BLOCKED
   622→FAILED
   623→NEEDS_CONTEXT
   624→NEEDS_TOOL
   625→NEEDS_IDENTITY
   626→```
   627→
   628→Examples:
   629→
   630→### NEEDS_CONTEXT
   631→
   632→The worker lacks information necessary to perform the task.
   633→
   634→### NEEDS_IDENTITY
   635→
   636→The requested test requires an identity that has not been configured.
   637→
   638→### BLOCKED
   639→
   640→A deterministic limitation prevented execution.
   641→
   642→The scheduler must handle these states.
   643→

   646→# 18. Task Lifecycle
   647→
   648→Implement:
   649→
   650→```text
   651→CREATED
   652→QUEUED
   653→READY
   654→RUNNING
   655→WAITING
   656→COMPLETED
   657→PARTIAL
   658→FAILED
   659→CANCELLED
   660→EXPIRED
   661→```
   662→
   663→Task transitions must be deterministic.

   667→# 19. Task Dependencies
   668→
   669→Tasks may depend on other tasks.
   670→
   671→Example:
   672→
   673→```text
   674→TASK A:
   675→discover endpoint
   676→
   677→       ↓
   678→
   679→TASK B:
   680→authenticate
   681→
   682→       ↓
   683→
   684→TASK C:
   685→replay endpoint with authenticated identity
   686→```
   687→
   688→Represent dependencies explicitly.
   689→
   690→Do not rely on model memory.
   691→
   692→---
   693→
   694→# 20. Task Priority
   695→
   696→Implement priority scoring.
   697→
   698→Initial factors:
   699→
   700→```text
   701→hypothesis confidence
   702→potential impact
   703→expected information gain
   704→test cost
   705→scope relevance
   706→novelty
   707→dependency readiness
   708→previous failure penalty
   709→```
   710→
   711→Do not use severity alone.
   712→
   713→A low-severity observation that can unlock the entire attack surface may deserve higher priority.
   714→
   715→---
   716→
   717→# 21. Expected Information Gain
   718→
   719→Introduce an information-gain concept.
   720→
   721→For each candidate test, estimate:
   722→
   723→```text
   724→expected_information_gain
   725→```
   726→
   727→A test is valuable when its result will significantly distinguish competing hypotheses.
   728→
   729→Example:
   730→
   731→```text
   732→H1: stale session
   733→H2: authorization cache
   734→H3: old API version
   735→```
   736→
   737→A test that distinguishes H1 vs H2 may be more useful than three generic scans.
   738→
   739→This is a key mechanism for autonomous reasoning.
   740→

   809→
   810→Every hypothesis should have evidence relationships.
   811→
   812→Example:
   813→
   814→```text
   815→H_17
   816→  |
   817→  +-- OBS_301
   818→  +-- OBS_302
   819→  +-- TEST_900
   820→  +-- EVD_111
   821→```
   822→
   823→This makes reasoning auditable.

   826→
   827→# 25. Confidence Updates
   828→
   829→Confidence must not be changed arbitrarily.
   830→
   831→Use evidence events.
   832→
   833→Conceptually:
   834→
   835→```text
   836→initial hypothesis
   837→        ↓
   838→supporting observation
   839→        ↓
   840→confidence increase
   841→        ↓
   842→contradictory observation
   843→        ↓
   844→confidence decrease
   845→        ↓
   846→verification
   847→        ↓
   848→confirmed/disproved
   849→```
   850→
   851→The exact mathematical model may initially be heuristic.
   852→
   853→Keep the scoring function replaceable.
   854→
   855→---
   856→
   857→# 26. Competing Hypotheses
   858→
   859→Do not force the leader to select one explanation prematurely.
   860→
   861→Example:
   862→
   863→```text
   864→Observation:
   865→"Endpoint returns different data depending on identifier."
   866→
   867→Hypotheses:
   868→
   869→H1: IDOR
   870→H2: role-based filtering
   871→H3: caching anomaly
   872→H4: intentionally public data
   873→```
   874→
   875→The system should preserve all viable explanations until evidence eliminates them.
   876→
   877→This is especially important in CTFs.
   878→
   879→---
   880→
   881→# 27. Dead-End Memory
   882→
   883→Create:
   884→
   885→```text
   886→dead_ends
   887→```
   888→
   889→Fields:
   890→
   891→```text
   892→id
   893→engagement_id
   894→hypothesis_id
   895→description
   896→tests
   897→reason
   898→created_at
   899→```
   900→
   901→Example:
   902→
   903→```text
   904→H_22:
   905→"JWT algorithm confusion"
   906→
   907→Tested:
   908→- token mutation
   909→- signature behavior
   910→- algorithm substitution
   911→
   912→Result:
   913→server rejects all altered tokens.
   914→
   915→Status:
   916→LOW PRIORITY / DEAD END
   917→```
   918→
   919→The leader should see this before proposing the same investigation again.
   920→

   924→
   925→Create a persistent record of every meaningful test.
   926→
   927→Fields:
   928→
   929→```text
   930→id
   931→engagement_id
   932→task_id
   933→hypothesis_id

   935→target

   950→
   951→Create deterministic test fingerprints.
   952→
   953→For example:
   954→
   955→```text
   956→hash(
   957→  endpoint
   958→  +
   959→  method
   960→  +
   961→  identity
   962→  +

   972→
