     8→     8→
     9→     9→# 0. Purpose
    10→    10→
    11→    11→Implement the **Security Reasoning Engine**.
    12→    12→
    13→    13→Part 3 gave the platform the ability to interact with an authorized web application.
    14→    14→
    15→    15→Part 4 gives it the ability to understand what those interactions mean from a security perspective.
    16→    16→
    17→    17→The system must transform:
    18→    18→
    19→    19→```text
    20→    20→raw requests
    21→    21→raw responses
    22→    22→browser events
    23→    23→DOM
    24→    24→JavaScript
    25→    25→WebSockets
    26→    26→identities
    27→    27→workflow events
    28→    28→source artifacts
    29→    29→```
    30→    30→
    31→    31→into:
    32→    32→
    33→    33→```text
    34→    34→attack surface
    35→    35→endpoints
    36→    36→parameters
    37→    37→assets
    38→    38→identities
    39→    39→sessions
    40→    40→workflows
    41→    41→state transitions
    42→    42→data flows
    43→    43→relationships
    44→    44→anomalies
    45→    45→hypotheses
    46→    46→tests
    47→    47→evidence
    48→    48→findings
    49→    49→```
    50→    50→
    51→    51→The central principle is:
    52→    52→
    53→    53→> **Do not ask an LLM to rediscover structure that deterministic software can extract.**
    54→    54→
    55→    55→Use deterministic extraction first.
    56→    56→
    57→    57→Use the LLM for interpretation, prioritization, hypothesis generation, and strategy.
    58→    58→

   122→   122→# 2. Do Not Build a Checklist Scanner
   123→   123→
   124→   124→Do not implement Part 4 as:
   125→   125→
   126→   126→```text
   127→   127→SQLi
   128→   128→XSS
   129→   129→IDOR
   130→   130→CSRF
   131→   131→SSRF
   132→   132→...
   133→   133→```
   134→   134→
   135→   135→followed by blindly running every test.
   136→   136→
   137→   137→Instead implement:
   138→   138→
   139→   139→```text
   140→   140→Observation
   141→   141→→ Security Signal
   142→   142→→ Hypothesis
   143→   143→→ Expected Evidence
   144→   144→→ Test
   145→   145→→ Result
   146→   146→→ Hypothesis Update
   147→   147→→ Next Test
   148→   148→```
   149→   149→
   150→   150→The system should prioritize tests based on evidence.
   151→   151→

   180→   180→# 4. Attack Surface Graph
   181→   181→
   182→   182→Create a graph representation of the engagement.
   183→   183→
   184→   184→Nodes can include:
   185→   185→
   186→   186→```text id="q2f4v8"
   187→   187→ENGAGEMENT
   188→   188→TARGET
   189→   189→HOST
   190→   190→PORT
   191→   191→APPLICATION
   192→   192→PAGE
   193→   193→ENDPOINT
   194→   194→PARAMETER
   195→   195→FORM
   196→   196→SCRIPT
   197→   197→API
   198→   198→WEBSOCKET
   199→   199→IDENTITY
   200→   200→SESSION
   201→   201→OBJECT
   202→   202→WORKFLOW
   203→   203→STATE
   204→   204→SOURCE_FILE
   205→   205→ARTIFACT
   206→   206→HYPOTHESIS
   207→   207→FINDING
   208→   208→```
   209→   209→
   210→   210→Edges represent relationships.
   211→   211→
   212→   212→Examples:
   213→   213→
   214→   214→```text id="v7h3k2"
   215→   215→PAGE ──contains──> FORM
   216→   216→PAGE ──loads──> SCRIPT
   217→   217→PAGE ──calls──> ENDPOINT
   218→   218→ENDPOINT ──accepts──> PARAMETER
   219→   219→IDENTITY ──owns──> SESSION
   220→   220→IDENTITY ──accesses──> OBJECT
   221→   221→ENDPOINT ──belongs_to──> APPLICATION
   222→   222→WORKFLOW ──contains──> STATE
   223→   223→STATE ──transitions_to──> STATE
   224→   224→HYPOTHESIS ──concerns──> ENDPOINT
   225→   225→EVIDENCE ──supports──> HYPOTHESIS
   226→   226→```
   227→   227→
   228→   228→---
   229→   229→
   230→   230→# 5. Graph Must Be Persistent
   231→   231→
   232→   232→Do not keep the attack graph only in memory.
   233→   233→
   234→   234→Persist nodes and relationships.
   235→   235→
   236→   236→Recommended relational representation:
   237→   237→
   238→   238→```text id="q9z8m4"
   239→   239→attack_nodes
   240→   240→attack_edges
   241→   241→```
   242→   242→
   243→   243→Optionally introduce a graph database later if scale requires it.
   244→   244→
   245→   245→Do not add a graph database merely because the system has a graph.
   246→   246→
   247→   247→PostgreSQL is sufficient initially.
   248→   248→

   270→   270→# 7. Endpoint Canonicalization
   271→   271→
   272→   272→Different observations may represent the same endpoint.
   273→   273→
   274→   274→For example:
   275→   275→
   276→   276→```text
   277→   277→/api/user/1
   278→   278→/api/user/2
   279→   279→/api/user/3
   280→   280→```
   281→   281→
   282→   282→may represent:
   283→   283→
   284→   284→```text
   285→   285→/api/user/{id}
   286→   286→```
   287→   287→
   288→   288→Do not immediately assume this.
   289→   289→
   290→   290→Create canonicalization candidates.
   291→   291→
   292→   292→Track:
   293→   293→
   294→   294→```text id="k7m2p1"
   295→   295→observed URL
   296→   296→canonical candidate
   297→   297→confidence
   298→   298→evidence
   299→   299→```
   300→   300→
   301→   301→The leader can later confirm or reject the abstraction.
   302→   302→
   303→   303→---
