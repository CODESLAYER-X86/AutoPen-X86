     1→# Autonomous Web Pentesting & CTF System
     2→
     3→## Implementation Specification — Part 4 of 8
     4→
     5→### Attack-Surface Intelligence, Authentication/Authorization Mapping, Workflow Analysis, Data Flow, Mutation, Differential Testing, Hypotheses, Anomaly Detection, and Verification
     6→
     7→---
     8→
     9→# 0. Purpose
    10→
    11→Implement the **Security Reasoning Engine**.
    12→
    13→Part 3 gave the platform the ability to interact with an authorized web application.
    14→
    15→Part 4 gives it the ability to understand what those interactions mean from a security perspective.
    16→
    17→The system must transform:
    18→
    19→```text
    20→raw requests
    21→raw responses
    22→browser events
    23→DOM
    24→JavaScript
    25→WebSockets
    26→identities
    27→workflow events
    28→source artifacts
    29→```
    30→
    31→into:
    32→
    33→```text
    34→attack surface
    35→endpoints
    36→parameters
    37→assets
    38→identities
    39→sessions
    40→workflows
    41→state transitions
    42→data flows
    43→relationships
    44→anomalies
    45→hypotheses
    46→tests
    47→evidence
    48→findings
    49→```
    50→
    51→The central principle is:
    52→
    53→> **Do not ask an LLM to rediscover structure that deterministic software can extract.**
    54→
    55→Use deterministic extraction first.
    56→
    57→Use the LLM for interpretation, prioritization, hypothesis generation, and strategy.
    58→

    78→                 |

    83→       |         |         |
    84→       v         v         v

    86→ Intelligence  Engine    Engine
    87→       |         |         |
    88→       +---------+---------+
    89→                 |
    90→                 v

    92→                 |

    95→                 |

   101→                 |

   122→# 2. Do Not Build a Checklist Scanner
   123→
   124→Do not implement Part 4 as:
   125→
   126→```text
   127→SQLi
   128→XSS
   129→IDOR
   130→CSRF
   131→SSRF
   132→...
   133→```
   134→
   135→followed by blindly running every test.
   136→
   137→Instead implement:
   138→
   139→```text
   140→Observation
   141→→ Security Signal
   142→→ Hypothesis
   143→→ Expected Evidence
   144→→ Test
   145→→ Result
   146→→ Hypothesis Update
   147→→ Next Test
   148→```
   149→
   150→The system should prioritize tests based on evidence.

   180→# 4. Attack Surface Graph
   181→
   182→Create a graph representation of the engagement.
   183→
   184→Nodes can include:
   185→
   186→```text id="q2f4v8"
   187→ENGAGEMENT
   188→TARGET
   189→HOST
   190→PORT
   191→APPLICATION
   192→PAGE
   193→ENDPOINT
   194→PARAMETER
   195→FORM
   196→SCRIPT
   197→API
   198→WEBSOCKET
   199→IDENTITY
   200→SESSION
   201→OBJECT
   202→WORKFLOW
   203→STATE
   204→SOURCE_FILE
   205→ARTIFACT
   206→HYPOTHESIS
   207→FINDING
   208→```
   209→
   210→Edges represent relationships.
   211→
   212→Examples:
   213→
   214→```text id="v7h3k2"
   215→PAGE ──contains──> FORM
   216→PAGE ──loads──> SCRIPT
   217→PAGE ──calls──> ENDPOINT
   218→ENDPOINT ──accepts──> PARAMETER
   219→IDENTITY ──owns──> SESSION
   220→IDENTITY ──accesses──> OBJECT
   221→ENDPOINT ──belongs_to──> APPLICATION
   222→WORKFLOW ──contains──> STATE
   223→STATE ──transitions_to──> STATE
   224→HYPOTHESIS ──concerns──> ENDPOINT
   225→EVIDENCE ──supports──> HYPOTHESIS
   226→```
   227→
   228→---
   229→
   230→# 5. Graph Must Be Persistent
   231→
   232→Do not keep the attack graph only in memory.
   233→
   234→Persist nodes and relationships.
   235→
   236→Recommended relational representation:
   237→
   238→```text id="q9z8m4"
   239→attack_nodes
   240→attack_edges
   241→```
   242→
   243→Optionally introduce a graph database later if scale requires it.
   244→
   245→Do not add a graph database merely because the system has a graph.
   246→
   247→PostgreSQL is sufficient initially.

   270→# 7. Endpoint Canonicalization
   271→
   272→Different observations may represent the same endpoint.
   273→
   274→For example:
   275→
   276→```text
   277→/api/user/1
   278→/api/user/2
   279→/api/user/3
   280→```
   281→
   282→may represent:
   283→
   284→```text
   285→/api/user/{id}
   286→```
   287→
   288→Do not immediately assume this.
   289→
   290→Create canonicalization candidates.
   291→
   292→Track:
   293→
   294→```text id="k7m2p1"
   295→observed URL
   296→canonical candidate
   297→confidence
   298→evidence
   299→```
   300→
   301→The leader can later confirm or reject the abstraction.
   302→
   303→---
   304→
   305→# 8. Endpoint Fingerprint
   306→
   307→Create deterministic endpoint fingerprints based on relevant properties such as:
   308→
   309→```text
   310→scheme
   311→host
   312→port
   313→normalized path
   314→method
   315→content type
   316→parameter structure
   317→```
   318→
   319→Do not include volatile values unless necessary.
   320→
   321→This prevents duplicate endpoint records.

   599→

   606→    ↓

   615→
   616→# 23. Authorization Map
   617→
   618→For each endpoint, maintain observed access matrix:
   619→
   620→| Endpoint   | Anonymous | User A   | User B   | Admin    |
   621→| ---------- | --------- | -------- | -------- | -------- |
   622→| endpoint A | observed  | observed | observed | observed |
   623→| endpoint B | denied    | allowed  | denied   | allowed  |
   624→
   625→Use statuses:
   626→
   627→```text
   628→ALLOWED
   629→DENIED
   630→REDIRECTED
   631→UNKNOWN
   632→ERROR
   633→```
   634→
   635→Do not equate HTTP 403 with every possible authorization denial.
   636→

   639→# 24. Cross-Identity Differential Analysis
   640→
   641→This is a major feature.
   642→
   643→Given:
   644→
   645→```text
   646→same request
   647→Identity A
   648→Identity B
   649→```
   650→
   651→compare:
   652→
   653→```text
   654→status
   655→headers
   656→body structure
   657→body values
   658→object references
   659→redirect
   660→timing
   661→error messages
   662→```
   663→
   664→The comparison must be semantic rather than only byte-for-byte.

   858→

   861→```text

  1098→# 45. Competing Interpretations

  1101→

  1165→

  1662→

  1667→> Try to determine whether the suspected vulnerability has an alternative explanation.
