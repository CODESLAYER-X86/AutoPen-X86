     8→     8→
     9→     9→# 0. Purpose
    10→    10→
    11→    11→Implement the agent operating system that sits between the application's persistent state and the security-testing tools.
    12→    12→
    13→    13→The system must support:
    14→    14→
    15→    15→* one strategic reasoning model
    16→    16→* multiple specialized tactical workers
    17→    17→* deterministic orchestration
    18→    18→* structured task creation
    19→    19→* hypothesis-driven investigation
    20→    20→* context-efficient worker prompts
    21→    21→* token/quota management
    22→    22→* task prioritization
    23→    23→* parallel and sequential execution
    24→    24→* evidence-driven replanning
    25→    25→* dead-end avoidance
    26→    26→* verification
    27→    27→* graceful failure
    28→    28→
    29→    29→The system must NOT become a collection of independent chatbots.
    30→    30→
    31→    31→There is one authoritative strategic controller.
    32→    32→
    33→    33→Workers are disposable tactical specialists.
    34→    34→
    35→    35→Persistent state belongs to the application.
    36→    36→

   159→   159→# 4. Strategic Leader
   160→   160→
   161→   161→The strategic model is the **commander**.
   162→   162→
   163→   163→Use the configured strategic model from Part 1.
   164→   164→
   165→   165→Do not hard-code a specific model identifier.
   166→   166→
   167→   167→Its responsibilities are:
   168→   168→
   169→   169→### Understand
   170→   170→
   171→   171→* engagement objective
   172→   172→* scope
   173→   173→* available identities
   174→   174→* discovered assets
   175→   175→* current attack surface
   176→   176→* challenge description
   177→   177→* relevant observations
   178→   178→
   179→   179→### Reason
   180→   180→
   181→   181→* identify promising attack surfaces
   182→   182→* generate hypotheses
   183→   183→* rank hypotheses
   184→   184→* recognize patterns
   185→   185→* interpret CTF clues
   186→   186→* identify missing information
   187→   187→* decide which investigation has the highest expected value
   188→   188→
   189→   189→### Plan
   190→   190→
   191→   191→* create investigation tasks
   192→   192→* order dependent tasks
   193→   193→* parallelize independent tasks
   194→   194→* request knowledge
   195→   195→* request browser investigation
   196→   196→* request HTTP investigation
   197→   197→* request source analysis
   198→   198→
   199→   199→### Replan
   200→   200→
   201→   201→After every meaningful result:
   202→   202→
   203→   203→* update hypotheses
   204→   204→* invalidate assumptions
   205→   205→* create new hypotheses
   206→   206→* abandon dead ends
   207→   207→* reprioritize tasks
   208→   208→* request verification
   209→   209→
   210→   210→### Stop
   211→   211→
   212→   212→Stop when:
   213→   213→
   214→   214→* objective is satisfied
   215→   215→* findings are sufficiently verified
   216→   216→* investigation budget is exhausted
   217→   217→* no meaningful hypotheses remain
   218→   218→* scope prevents further testing
   219→   219→* operator pauses/cancels
   220→   220→* system safety policy requires stopping
   221→   221→

   224→   224→# 5. Leader Must Not Become a Checklist Generator
   225→   225→
   226→   226→Do not implement:
   227→   227→
   228→   228→```text
   229→   229→recon
   230→   230→then auth
   231→   231→then SQLi
   232→   232→then XSS
   233→   233→then IDOR
   234→   234→...
   235→   235→```
   236→   236→
   237→   237→as the mandatory algorithm.
   238→   238→
   239→   239→Instead implement:
   240→   240→
   241→   241→```text
   242→   242→OBSERVATIONS
   243→   243→      ↓
   244→   244→HYPOTHESES
   245→   245→      ↓
   246→   246→EXPECTED INFORMATION GAIN
   247→   247→      ↓
   248→   248→TEST SELECTION
   249→   249→      ↓

   252→   252→HYPOTHESIS UPDATE
   253→   253→      ↓

   256→   256→
   257→   257→The security methodology is a source of candidate tests, not an inflexible sequence.

   429→   429→# 12. Gemma Worker Philosophy
   430→   430→
   431→   431→The tactical model should receive **small tasks**.
   432→   432→
   433→   433→Never send:
   434→   434→
   435→   435→```text
   436→   436→entire engagement
   437→   437→+
   438→   438→all requests
   439→   439→+
   440→   440→all responses
   441→   441→+
   442→   442→all source code
   443→   443→+
   444→   444→all knowledge
   445→   445→```
   446→   446→
   447→   447→Instead:
   448→   448→
   449→   449→```text
   450→   450→TASK
   451→   451→+
   452→   452→RELEVANT CONTEXT

   454→   454→RELEVANT EVIDENCE

   713→   713→A low-severity observation that can unlock the entire attack surface may deserve higher priority.
   714→   714→
   715→   715→---
   716→   716→
   717→   717→# 21. Expected Information Gain
   718→   718→
   719→   719→Introduce an information-gain concept.
   720→   720→
   721→   721→For each candidate test, estimate:
   722→   722→
   723→   723→```text
   724→   724→expected_information_gain
   725→   725→```
   726→   726→
   727→   727→A test is valuable when its result will significantly distinguish competing hypotheses.
   728→   728→
   729→   729→Example:
   730→   730→
   731→   731→```text
   732→   732→H1: stale session
   733→   733→H2: authorization cache
   734→   734→H3: old API version
   735→   735→```
   736→   736→
   737→   737→A test that distinguishes H1 vs H2 may be more useful than three generic scans.
   738→   738→
   739→   739→This is a key mechanism for autonomous reasoning.
   740→   740→
   741→   741→---

   827→   827→# 25. Confidence Updates
   828→   828→
   829→   829→Confidence must not be changed arbitrarily.
   830→   830→
   831→   831→Use evidence events.
   832→   832→
   833→   833→Conceptually:
   834→   834→
   835→   835→```text

   837→   837→        ↓
   838→   838→supporting observation
   839→   839→        ↓
   840→   840→confidence increase
   841→   841→        ↓
   842→   842→contradictory observation
   843→   843→        ↓
   844→   844→confidence decrease
   845→   845→        ↓
   846→   846→verification
   847→   847→        ↓
   848→   848→confirmed/disproved
   849→   849→```
   850→   850→
   851→   851→The exact mathematical model may initially be heuristic.
   852→   852→
   853→   853→Keep the scoring function replaceable.
   854→   854→

   857→   857→# 26. Competing Hypotheses
   858→   858→
   859→   859→Do not force the leader to select one explanation prematurely.

   862→   862→

   873→   873→```
   874→   874→
   875→   875→The system should preserve all viable explanations until evidence eliminates them.
   876→   876→
   877→   877→This is especially important in CTFs.
   878→   878→
